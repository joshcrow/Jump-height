# Audit 2026-08-22 — what is still open

The audit ran 21 tickets (F-01…F-21) across build gates, power, storage
integrity, the watch, BLE pinning, sim/firmware parity and test rigor. **All 21
are closed**, each one mutation-tested, and the OG was flashed and
desk-verified at `src=e83f6395`.

The per-ticket detail — 1,000 lines of it — was cut on 2026-08-23. It was a
record of finished work, and the 21 commit hashes it cited are the real record.
Read them with `git log`, or restore the full ledger:

```
git show archive/docs-2026-08-23:docs/audit-2026-08-22.md
```

Two of the audit's own premises were disproven by measurement while working it,
which is worth remembering before trusting any audit document, including this
one: F-08's prescribed fix would not have met its own acceptance criterion, and
F-18's "constants are triplicated" was wrong — the watch bounds differ on
purpose.

What survives below is the part that is still load-bearing: **the findings that
are open**, and **the theories that were investigated and killed**, so nobody
spends a second evening re-chasing them.

## Found while working the ledger (2026-08-23)

Added under the decision rule in `docs/audit-phase-prompts.md`: a fix that

### [ ] F-24 · minor · hand-verified — self-arm cannot bootstrap at a small lever arm

- **Location:** `sim/lever_arm.py` + `firmware/src/main.cpp:1634-1660` (the
  commit gate); exposed by `tools/tests/test_lever_arm.py`'s r=0.2 case
- **Defect:** the lever-arm estimator commits only on a VALIDATED jump, but at
  a small lever arm and high spin the flight that carries the observations is
  the one the detector REJECTS. Traced sample by sample at r=0.2 m / 600 dps,
  uncalibrated:

      t=2.925   64 observations   REJECTED    -> discard
      t=3.560    0 observations   validated   -> commit, with nothing to commit

  So the estimator never bootstraps. Larger radii work because their first
  AIRBORNE exit is itself validated.
- **Evidence:** `test_uncalibrated_device_fixes_itself_over_jumps[0.2]`, now
  `xfail(strict=True)`. It passed until F-17 only because the test was running
  the retired ungated commit policy — the same policy that corrupted
  calibration ~50×. There is no version of this that is both safe and passing
  today.
- **NOT REACHABLE ON THE DEVICE:** `JH_SPIN_SELFARM_ENABLED` is 0 — self-arm is
  compiled out for the one-shot water session. This is a design gap in a
  feature that is currently off, not a live defect.
- **Fix (not costed):** the estimator needs a bootstrap path that does not
  depend on a validated jump — e.g. accept observations from a flight rejected
  *for airtime reasons only* while still refusing the railed-gyro phantoms that
  motivated the gate. Distinguishing those two rejects is the actual work.
- **Do NOT fix by reverting the gate.** That is the ~50× corruption path, and
  the strict xfail exists so that reverting it announces itself.

### [ ] F-22 · minor · hand-verified — trace_bytes() over-reports once the region fills

- **Location:** `firmware/src/platform/nrf52/jh_store.cpp` — `trace_append()`
  accounting vs `walkTraceRegion()`
- **Defect:** the live counter adds each sample's CSV length as text arrives,
  but samples sit in an open block until it closes. Ordinarily that is a lag
  the next block write settles. Once the region is FULL it becomes permanent:
  `closeAndWriteBlock()` drops a block that no longer fits, and the bytes it
  held stay counted.
- **Evidence:** filling the region in the harness gives `TRACE_BYTES
  n=14476006` live, but a remount recomputes 14,475,206 — 800 bytes, exactly
  one 50-sample batch at 16 B/line. `TRACE_RECHECK` agrees with the remount, so
  the *stored* side is self-consistent; the live counter is the one that drifts.
- **Impact:** display only, and it self-corrects at the next boot. It reaches a
  rider as a `trace_bytes` in STATS slightly ahead of what a `dump` produces,
  at the one moment (a full region) they are most likely to compare the two.
- **Fix:** settle the counter against what was actually written when a block is
  dropped, or state in `jh_store.h` that `trace_bytes()` is an upper bound and
  make `tracecheck` the authority. Do NOT fix by making appends count only at
  block close — that would make the number lag ~5 s behind during a ride.
- **Found by:** F-08's parity work. Nothing else compares the two counters.

### [ ] F-23 · minor · hand-verified — full-chip mount is ~80× empty, and no counter scheme fixes it

- **Location:** `firmware/src/platform/nrf52/jh_store.cpp` — `walkTraceRegion()`
- **Defect:** F-08's acceptance asked for full-chip mount within ~10× of
  empty. After F-08 it is 74 ms vs 0.93 ms. The residue is not accounting: a
  floor probe with the counter replaced by a no-op still took 60 ms. The scan
  reads and CRC-checks every block in the region to find the append point.
- **Why the ticket's own fix would not have helped:** persisting cumulative
  totals in block headers removes the counting, not the walking. The walk is
  the floor.
- **Fix (real one, not costed):** find the erase boundary without decoding
  every block — a binary search over the region for the first erased page
  would be ~16 reads instead of ~19,000 blocks. This CONFLICTS with the
  deliberate torn-write behaviour of continuing past a damaged patch (a prior
  boot may have resumed appending beyond it), so it needs a design decision
  about which guarantee wins, not a local edit.
- **Impact:** bounded and already survivable — the scan feeds the watchdog
  every 64 blocks (a fix that predates this audit). It is boot latency on a
  well-used puck, not a failure.

### [x] F-25 · minor · CLOSED 2026-08-24 — `jump status` reports the help text and calls it the binary

> Both fix halves shipped: the tool label + dispatch-table diff on 08-23, and
> the help string itself in `42dbd59`, flashed to the OG the same night
> (`src=76df4a83`). `jump status` reads `commands advertised by help (21)`
> with no warning line. Original entry below, unchanged:

- **Location:** `tools/jump:2563-2567`; `firmware/src/main.cpp:613`
- **Defect:** `./tools/jump status` prints `commands in binary (N): ...`, but
  it derives that list by running `strings` over the ELF and taking the line
  beginning `# commands:` — which is the **help string**, not the dispatch
  table. Anything dispatched but not advertised is invisible to it. Today
  three commands are: `pincensus` (`main.cpp:735`), `gyro` (`main.cpp:1145`)
  and `vbatscan` (`main.cpp:1183`). So the tool says 18 where the binary
  handles 21.
- **Why it is not cosmetic:** the label makes a claim about the *binary*
  while the evidence supports only a claim about the *help text*, under a
  banner that reads "machine-checked; anything not checkable is marked
  UNKNOWN, never assumed." The specific casualty is `pincensus`: DECISION #38
  makes a census mandatory for any "this pin is stuck" statement, and a
  reader who checks availability the documented way concludes the instrument
  was never shipped. That is the 2026-08-14 shape again — the fact is present
  and correct, and nothing joins it to the screen.
- **Evidence:** `./tools/jump status` on the OG tonight printed
  `commands in binary (18)` with `pincensus`, `gyro` and `vbatscan` absent,
  against three live `else if (cmd == ...)` arms at the lines above.
- **Fix:** two halves, and the cheap one is the important one.
  1. **Relabel, no firmware change:** call it `commands advertised by help
     (N)`, so the claim matches the evidence. Free, correct today, needs no
     flash. Better still, parse the dispatch arms out of `main.cpp` and print
     the *difference* — an undocumented command is itself a finding.
  2. **Add the three to `main.cpp:613`** — but this touches silicon, so it
     rides the next flash batch and never triggers one of its own (CLAUDE.md
     rule 4).
- **Do NOT fix** by deleting the three commands to make the list true. They
  are working diagnostics; `pincensus` is doctrine.
- **Found by:** the 2026-08-23 documentation sweep, while establishing which
  tool outputs the docs were allowed to cite as evidence.

### [x] F-26 · minor · CLOSED 2026-08-25 — `sim/selfdiag.py` has no test at all

> Fixed by `tools/tests/test_selfdiag.py` (17 tests). Mutation score went
> 2/11 -> 5/11 -> **10/11 killed**: the first draft asserted far from every
> boundary and guarded almost nothing, which is F-26's own lesson landing on
> F-26's fix. The last survivor (`n % 2` -> `n % 2.5`) is equivalent on the
> tested window lengths. Original entry below:

- **Location:** `sim/selfdiag.py`; no file under `tools/tests/` imports it
- **Defect:** the 2026-08-24 mutation campaign broke all 11 mutable
  constants and comparisons in this module — every threshold, every gate —
  and **all 11 survived a full 223-test run.** Not one test noticed. Its
  only exercise is inside `sim/experiments/*.py`, which are analysis
  scripts run by hand, not gates: nothing in `simtest` or CI runs them, so
  a regression here is invisible until someone re-runs an experiment.
- **Why it matters:** this is the non-ballistic self-diagnostic — the thing
  that flags a jump whose height is biased by sustained wing lift, which is
  DECISION #30's documented silent-failure class and the *only* automated
  warning the water day has for it. Its own header calls the flag
  "CONSERVATIVE: it can't under-warn" — a property nothing verifies.
- **Evidence:** `mutation-report.json`, 11/11 SURVIVED (e.g. `selfdiag.py:45
  const 0.15->0.1875`, `:46 const 0.08->0.1`, `:64 const 0.12->0.15`). The
  campaign's baseline was green first, so the verdicts are meaningful.
- **Fix:** a small property test for the conservatism claim — a jump with
  known specific force must flag, and the flag must never be quieter than
  the vertical component alone. Cheap; the physics is already in
  `sim/wing_model.py` and `e3_selfdiag_roc.py` has the ROC scaffolding.
- **NOT a water-day blocker:** the module is offline analysis, not firmware.
  Nothing on the puck depends on it.

### [x] F-27 · minor · CLOSED 2026-08-25 — `--split` filtering in `jump eval` is unguarded

> Fixed by `SplitFilterTest` in `tools/tests/test_evaluate.py` (4 tests,
> incl. a partition property: train and test must be disjoint AND cover the
> corpus). The original `NotEq->Eq` mutant is now KILLED. Original entry:

- **Location:** `sim/evaluate.py:424`
- **Defect:** inverting the split-filter comparison (`NotEq->Eq`, i.e.
  selecting exactly the sessions it should exclude) survives the full
  suite. Independently predicted the night before by the agent that fixed
  the evaluator ("`--split` on an excluded session is untested territory")
  and now confirmed mechanically.
- **Impact:** bounded today — no session in the corpus carries a `split`,
  so the filter is inert. It stops being inert the moment held-out
  evaluation starts, which is exactly when a silently-inverted filter would
  train and validate on the same sessions.
- **Fix:** one test with two sessions, one `train` one `test`, asserting
  each `--split` value scores only its own.

## Refuted — do not re-chase

Raised, investigated, and killed by skeptics. Listed so agents don't
rediscover them:

- **main.cpp:1500 "double-counted jumps"** — mechanism real (unconditional
  increment), but the jumps list re-derives from flash; user-facing counts
  self-correct. Residual interface debt is F-10.
- **JumpFieldView.mc draw-loop allocation / font re-fitting** — refuted on
  cost: allocation volume is within Monkey C GC noise at 1 Hz; no retained
  growth (data layer audited at zero bytes/jump).
- **PuckLink.mc:314 puckName-inert / UUID-first matching** — mechanism
  accurate but intended: UUID-in-advert is the firmware's design; RSSI
  selection among own pucks acceptable. The timeout gap at :186 (F-12) is
  the real finding.
- **sim/windows.py Goertzel & delta-sort "O(n²)"** — reproduces, but runs on
  ~4,000-sample bench traces: milliseconds. Not worth churn.
- **trace_codec.h:156 milli_g rounding divergence C++ vs Python** — real
  divergence (32,765 float32 inputs), but every reachable input is clamped
  upstream; bit-parity holds on the reachable domain.
- **lsm6ds3_min.h two-burst read → one 12-byte burst** — contiguous registers
  confirmed, but the measured saving doesn't clear the noise floor and the
  fix breaks the accel-only fallback path.
- **"unittest discover misses tests" as a CI problem** — CI runs pytest and
  is whole; the gap is local simtest only (F-02 as scoped).
- **tools/jump:2481 nine BLE scans in `boards`** — real but bench-only
  wall-clock; the data-integrity half (F-15) is what survived.
